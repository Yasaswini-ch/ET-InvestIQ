2) Logical Agent Roles

  1. Portfolio Analyst Agent (/api/xray): CAS interpretation, health, overlap, rebalancing.
  2. Radar Intelligence Agent (/api/radar): feed fusion, normalization, quote enrichment, conviction ranking.
  3. Market Chat Agent (/api/chat): conversational market + portfolio context via chat provider router.
  4. Chart Pattern Agent (/api/charts): deterministic OHLCV analytics + AI interpretation.
  5. Scam Detection Agent (/api/scamcheck): fraud/urgency detection with safe fallback.
  6. Briefing Agent (/api/briefing): actionable daily summary with fallback object.
  7. Intelligence Center Agents (/api/intelligence/*): budget, promoters, and stay-course analysis.
  8. SIP Planning Engines (/api/sip, /api/sipoptimizer, /api/stress): deterministic finance math + targeted AI narrative.

3) Communication and Data Flow

  1. User action in UI triggers route-specific API call.
  2. Route applies IP-based throttling via lib/rateLimit.ts.
  3. Route builds deterministic context from feeds, quotes, and local portfolio context.
  4. Route calls model provider only when needed (OpenRouter for chat, Gemini elsewhere).
  5. If provider fails, route returns deterministic fallback payload.
  6. UI renders loading/error/empty states without runtime crash.

4) Tool Integrations

  • LLM: lib/gemini.ts, lib/chat/llm.ts
  • Market Data: lib/yfinance.ts, lib/feeds/*
  • Client Context: localStorage for xray context, investor profile, and learning progress
  • Visualization: Recharts + Lightweight Charts

5) Error Handling and Resilience

  • Rate-limit guard and 429 responses on API burst traffic
  • Provider fallback for Gemini/OpenRouter failures
  • Curated radar fallback when live feeds fail
  • Dynamic GET route strategy to prevent build-time quota burn
  • Prompt-injection filters + message length/count guards in chat
  • UI-level null/empty guards and loading indicators

6) Deployment Notes

  • Keep GEMINI_API_KEY for non-chat AI routes.
  • Use chat-specific vars: CHAT_PROVIDER, CHAT_OPENROUTER_API_KEY, CHAT_OPENROUTER_MODEL or CHAT_OPENROUTER_MODEL_LIST.
  • Validate Production env vars on Vercel before chat verification.
